# 엑셀과 AI, 어디까지 왔나
최근 엑셀에도 AI 에이전트를 도입하려는 시도가 많아지고 있습니다. **Excel MCP 서버**를 연결해 로컬 엑셀 파일을 직접 다루는 방법도 있고, **Microsoft Copilot**이나 **Genspark** 등에서도 엑셀을 AI로 다룰 수 있는 서비스를 제공하고 있습니다.

지금까지 나온 거의 모든 엑셀 관련 AI 에이전트를 직접 사용해봤지만, 회계·재무 실무에서 가장 뛰어난 퍼포먼스를 보여준 것은 결국 **클로드 엑셀(Claude for Excel)** 이었습니다.

# 자연어로 일을 시키는 엑셀 애드인
클로드 엑셀은 **앤트로픽(Anthropic)** 에서 개발한 엑셀 애드인으로, 엑셀 파일 내에서 클로드 에이전트를 챗봇처럼 사용할 수 있는 프로그램입니다.

- 사용자가 자연어로 대략적인 요구사항만 설명해도 알아서 **작업 계획**을 세움
- 모호하거나 누락된 부분은 다시 **질문을 통해 보완**한 후 작업 실행
- 단순 함수 입력이 아니라 **여러 시트·여러 단계 작업**을 한 번에 처리
- 결과물에 대해 **사후 검토와 수정** 요청도 자연어로 가능

VBA/Python 매크로처럼 사전 코드를 작성할 필요 없이, 실무자가 평소 동료에게 일을 부탁하듯 지시할 수 있다는 점이 가장 큰 차별점입니다.

# 클로드 엑셀의 세 가지 핵심 기능

### 스킬 (Skills)

전문지식을 학습시키고 구체적인 엑셀 작업을 일관되게 지시할 수 있는 AI 업계 혁신 기능. 회계·감사 표준 절차를 매뉴얼화 가능.

### 커넥터 (MCP)

엑셀 업무와 관련된 다양한 외부 서비스를 연결하여 업무 프로세스에 자연스럽게 녹여낼 수 있음. ERP·DART·내부 DB와 직결.

### 클로드 파워포인트 연동

엑셀 시트를 기반으로 PPT 보고서까지 한 번에 생성하는 워크플로우가 현실이 됨. 결산·감사 보고서 1-step 산출 가능.

# AI와 기존 자동화(VBA, Python)의 차이
흔히 엑셀 자동화라고 하면 **VBA**나 **Python**을 떠올리기 쉽습니다. 그렇다면 클로드 엑셀과 같은 AI 도구는 기존의 프로그래밍 방식과 어떤 점이 다를까요?

<div class="callout info">

**핵심 차이: 알고리즘 vs 추론**

VBA·Python 같은 프로그래밍 언어는 **'사전에 정해진 알고리즘'** 대로만 기계적으로 완벽하게 반복 작동합니다. 반면 확률 모델 기반 AI는 상황을 스스로 파악하고 가장 적절한 방법을 **'추론하여 유연하게 실행'** 합니다. 기존 자동화는 **반복 작업에 절대적 강점**, AI 에이전트는 **융통성·직관·맥락 추론에 강점**.

</div>

<div class="note">

상황 추론으로 인한 **비일관성**은 AI의 단점이지만, 최근 등장한 **스킬(Skills)** 기능이 이를 보완합니다.

</div>

# Settings — 4가지 핵심 옵션

### User Instructions

모든 작업에 공통 적용할 '업무 매뉴얼'. "답변은 한국어로", "수정 셀은 연노란색 배경" 같은 지침을 미리 입력해두면 매번 지시 불필요.

### Let Claude suggest improvements <span class="tag green">활성화 권장</span>

지시받은 작업만 수행하지 않고 **더 효율적인 방식·오류 가능성을 능동적으로 제안**. 함수 추천, 데이터 구조 개선까지.

### Session logging <span class="tag green">활성화 권장</span>

모든 작업 내역을 별도의 `Claude Log` 시트에 기록. 컨텍스트 압축 시 로그가 있으면 **요약 정확도와 일관성**이 크게 향상.

### Let Claude work across files <span class="tag peach">비활성화 권장</span>

열려 있는 **모든 Excel·PowerPoint 파일**의 컨텍스트 공유. 강력하지만 민감 데이터 노출 위험 → 필요시에만 활성화.

# 모델 선택 — Opus vs Sonnet

현재 클로드 엑셀에서는 **Opus 4.6, Opus 4.5, Sonnet 4.6** 세 모델을 지원합니다. Sonnet 4.6과 Opus 4.6은 **100만(1M) 토큰**[^1]의 방대한 컨텍스트 창을 제공해 수십 개 시트가 얽힌 거대 워크북 전체 분석이 가능합니다.

![w:680](https://raw.githubusercontent.com/procpalee/my_obsidian_images/master/20260315144854849.png)

놀랍게도 Sonnet이 **Agentic financial analysis·Office tasks**에서는 Opus보다 성능이 더 뛰어난 것으로 평가되었습니다.

<div class="callout info">

**플랜별 모델 선택 가이드** — 토큰 소모량이 넉넉한 **Max 유저**는 **Opus 4.6**을 기본으로, **Pro 유저**는 속도·가성비 압도적인 **Sonnet 4.6**만으로도 충분히 만족스러운 성능을 경험할 수 있습니다.

</div>

[^1]: 100만 토큰은 약 75만 단어 이상을 한 번에 처리할 수 있는 양 — 일반 소설책 수십 권 분량.

# 클로드 엑셀의 6대 기능

### 데이터 구조 분석

여러 시트·탭을 넘나들며 **전체 워크북 구조** 파악. 시트 간 참조 관계를 정리·요약.

### 파일 편집

단순 셀 편집부터 스프레드시트를 처음부터 생성까지. 수식 오류(`#REF!`/`#VALUE!`) 추적·수정 + 피벗·차트·조건부 서식.

### 지침(Instructions) 설정

시스템 프롬프트로 포맷·스타일 규칙을 모든 세션에 일관 적용.

### 외부 데이터 커넥터 (MCP)

S&P Global, FactSet 등 외부 금융 데이터를 실시간 연동. DART·공공데이터포털 자체 구축도 가능.

### 사용자 정의 스킬 (Skills)

반복 작업·전문지식을 스킬로 정의해 필요시 호출. **DCF 모델링 스킬** 같은 고도화 자동화 가능.

### 외부 파일 읽기

업로드된 PDF·DOCX·CSV·JSON·XML 등을 파싱해 엑셀로 추출. 이미지·구형 포맷은 제한.

# 지침(Instructions) 설정

시스템 프롬프트(Instructions)를 설정하여 포맷 규칙이나 스타일 가이드를 모든 세션에 일관되게 적용할 수 있습니다.

<div class="callout example">

**지침 설정 예시**

- "모든 세션에서 입력값은 **파란색**, 단순 참조값은 **초록색**, 수식값은 **검정색**으로 표시해줘"

# 외부 파일 읽기 — 지원 범위

| 파일 종류 | 지원 확장자 | 한계 및 우회 팁 |
|---|---|---|
| **스프레드시트** | `.xlsx`, `.csv` | <span class="tag green">완전 지원</span> CSV·서식 최소화 Excel 권장 |
| **문서 파일** | `.pdf`, `.docx` | <span class="tag yellow">조건부</span> 텍스트·표 OK / 스캔 PDF 불가 |

| **지원 불가** | `.jpg`, `.hwp`, `.doc` | <span class="tag rose">불가</span> 한글(.hwp)은 PDF/DOCX로 재저장 |

<div class="callout warn">

# 엑셀과 Open XML
우리가 흔히 사용하는 엑셀 파일(`.xlsx`)은 사실 **Office Open XML (OOXML)** 표준 포맷으로 만들어져 있습니다. `.xlsx`의 확장자를 `.zip`으로 변경하고 압축을 풀면 내부가 여러 폴더와 **XML 파일들의 집합**임을 확인할 수 있습니다.

- **워크북 구조**: `workbook.xml`
- **각 시트 데이터**: `sheet1.xml`, `sheet2.xml`, …
- **텍스트 데이터**: `sharedStrings.xml`

결과적으로 **엑셀 파일을 수정한다는 것은 내부 XML 파일들의 코드를 수정하는 것과 동일**합니다. LLM은 본질적으로 텍스트·코드(특히 XML 같은 마크업 언어) 처리에 특화되어 있어, 엑셀의 뼈대인 XML을 이해하고 조작하는 것이 매우 자연스럽고 잘 할 수 있는 영역입니다.

<div class="callout info">

**클로드의 지원 파일 포맷** — Open XML 기반 **.xlsx, .pptx, .docx**만 완벽 해독·지원. 구형 포맷(**.xls, .ppt, .doc**)은 정상 조작 불가 → 최신 포맷으로 변환 후 사용.

</div>

# Python vs Office.js — 핵심 차이

<div class="col">

## Python (Openpyxl + Pandas)

- **Openpyxl** — `.xlsx` 파일을 셀 단위로 읽고 쓰는 라이브러리. 셀 값·수식 텍스트·서식 추출 가능
- **Pandas** — 표 형태 데이터의 **대량 처리**에 특화 (필터·그룹·피벗·통계)
- **디스크에 저장된 엑셀파일**을 대상으로 동작
- 현재 열려 있는 문서가 아니라 **업로드된 파일**을 별도로 읽어서 분석

</div>

<div class="col">

## Office.js

- Microsoft 공식 JavaScript API
- 엑셀 앱 내부 **브라우저 샌드박스(WebView)**에서 실행
- 현재 열려 있는 문서의 셀·시트·차트를 **즉시 읽고 쓰기**
- 셀·시트 조작, 테이블/차트/피벗/조건부 서식, 데이터 유효성 검사, 이벤트 감지까지 광범위 지원

</div>

# 클로드 엑셀의 작동 순서

1. **현재 문서 상태 읽기** — 사용자가 메시지를 보내면 클로드는 먼저 Office.js를 통해 시트 구성·활성 시트·데이터 범위·수식·서식 등 워크북의 "현재 상황"을 파악
2. **작업 계획 수립** — 문서 상태와 지시를 종합해 어떤 작업을 어떤 순서로 수행할지 계획. 현재 문서 직접 조작 → Office.js / 외부 파일 분석 → Python / 둘 다 필요 → Python 후 Office.js
3. **코드 생성 및 실행** — 계획에 맞는 코드를 직접 생성하고 실행. Office.js는 엑셀 내 샌드박스, Python은 외부 컨테이너에서 실행
4. **결과 확인 및 후속 조치** — Office.js로 결과 상태를 다시 확인. 수식 오류나 의도와 다른 결과 발견 시 스스로 수정 시도 또는 사용자에게 확인 요청
5. **자기 점검 → 수정 루프** — 이 사이클이 클로드 엑셀을 단순 코드 실행기가 아닌 **에이전트**로 동작하게 하는 핵심 원리
