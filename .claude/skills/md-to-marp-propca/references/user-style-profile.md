# 사용자 스타일 프로파일 (PROCPA) — 변환 시 필수 로드

기존 산출물(한공회 39장 덱, 블로그 원고, 카드뉴스 샘플)에서 역추출해 **사용자가 검수 확정한** 개인 스타일 규칙(2026-07). **procpa-vivid / 카드뉴스 변환 시 레이아웃 매칭과 함께 항상 적용**한다.

## 화자 정체성

- 화자: **현직 공인회계사 + AI 실사용 검증자 (PROCPA)**. 개발자 시점이 아니라 실무자 시점.
- 기본 독자: **비개발자 회계·재무·세무 실무자**. 개발 용어에는 실무 비유를 붙인다 (예: MCP = 범용 어댑터).
- 예시 소재는 회계 실무(원장·시산표·DCF·감가상각·공시)에서 우선 선택.
- AI 낙관론·과장 사례에는 회의적 균형을 유지 ("베스트 케이스 편집일 가능성").
- 보안·데이터 관련 주제에는 법적 한계 고지를 포함한다.

## 문체 — 매체별 3단 스위칭 (가장 뚜렷한 시그니처)

| 매체 | 종결 |
|---|---|
| 산문·발표 리드문·카드 서브텍스트 | "~합니다/~입니다" 경어체 |
| 슬라이드/카드 불릿 | 명사형 종결 (체언 종결, 어미 생략) |
| 해요체 | 기본은 안 쓰되 완전 금지 아님 — 카드뉴스 CTA 등 가벼운 마무리에서 선택적 허용 |

- 섹션 도입에 **자문자답** 1회 이상: 수사 의문문("왜 그럴까요?") → 바로 한 문장 단정으로 답.
- 단정형이 기본, 개인 견해는 "저는 ~라고 생각합니다/판단합니다"로 표지.
- 전문용어 최초 등장 시 **한글(영문) 괄호 병기**: 클로드 엑셀(Claude for Excel), 암묵지(Tacit Knowledge).
- 시그니처 어휘 우선 사용: 불확정성 · 암묵지 · 자가 검증 · 하네스 엔지니어링 · 실무자 · 도메인 지식 · "생각보다 더" · "결국 ~로 귀결됩니다" · "선택이 아닌 필수".
- 개념 스포트라이트에 작은따옴표: '불확정성', '실행'.
- 리듬: 긴 문장 뒤 짧은 단정문 ("역사는 반복됩니다.").

## 슬라이드 밀도

- 슬라이드당 불릿 **3~6개**, 불릿당 **45자 이내**. 7개 이상 금지 → 분할.
- 불릿 기본형: "**볼드 키워드**: 설명 한 줄".
- 한 장 = 한 주제 + (리드 1문장) + 불릿/카드 + (선택) 콜아웃 1개.
- 실습·사례는 **상황 → 프롬프트 → 진행과정 → 결과** 4장 분할이 고정 패턴.
- 병렬 나열은 **3개 단위** 우선 (전략 3가지, 카드 3장, 결론 3가지).
- 도구 시연은 스크린샷+설명 `split`이 기본값.

## 강조 정책

- 볼드는 문단·불릿당 **1~2개**, 개념 명사구에만. 문장 전체 볼드 금지.
- 슬라이드 하단 `.callout` 1개로 "포인트/주의/역할분담" 한 줄 요약 — ⚠️ 주의=`warn`, 결론·포인트=`success`, 대구(對句)형 한 줄("반복 수작업은 MCP가, 판단은 사람이")은 기본 callout.
- 숫자는 개수 프레임(N가지·N단계·N원칙)으로 구조화, 비율은 어림 범위(80~90%).
- 데이터 인용 시 출처(인물·기관)를 문장 안에 자연스럽게 병기.

## 덱 구성 골격

1. `cover` — H1 제목 + H2 부제 + 연월 (발표자명 ❌)
2. `toc` — 챕터명 + `<em>`으로 세부 키워드 가운뎃점(·) 나열
3. "시작하며" — 공감형 후크: 통념 인용 + 반문("~라는데 왜 내 실무는 그대로일까?") → 원인 한 문장 단정 (`statement` 또는 `statement light`)
4. 본론 — 진단(한계) → 처방(전략 N가지) → 실증(사례). 섹션 제목은 "01 + 명사구"
5. 챕터 전환부마다 `takeaway`/`statement`로 핵심 1문장 독립 (덱당 1~3장)
6. "마치며" — 비교 참고 → `qa`("무엇이든 물어보세요") → `thanks-contact`(아래 고정 세트) → `end`("감사합니다")
