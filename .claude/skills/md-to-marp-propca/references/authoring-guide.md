# 소스 마크다운 작성 가이드 — "이렇게 쓰면 이렇게 나온다"

옵시디언(또는 표준 마크다운)에서 원고를 **어떻게 쓰면** procpa-vivid 변환이 원하는 레이아웃으로 떨어지는지의 치트시트. 변환 품질은 매칭 규칙보다 소스 구조가 좌우한다 — 원고 단계에서 이 신호를 심어두면 수동 교정이 거의 없어진다.

## 치트시트 — 소스 패턴 → 산출 레이아웃

| 원고에 이렇게 쓰면 | 이렇게 나온다 |
|---|---|
| 문서 맨 위 `# 제목` + 부제 한 줄 | `cover` (H1+H2+연월) |
| `## 1. …` H2 챕터 구조 | `section` 구분 + `toc` 자동 구성 |
| 문단 + 스크린샷 1장 | `split` (좌 텍스트 / 우 프레임 이미지) |
| **볼드 키워드**: 설명 불릿 3~6개 | 기본 본문 (불릿 형식 유지) |
| 굵은 소제목 3개 + 각 1~2문장 | `.cols-3` + `.card` 또는 `feature-cards` |
| "A vs B", "~와 ~의 차이" 문구 + 양쪽 특성 | `.vs` / `comparison-vs` |
| 마크다운 표 | `.table-block`(회계 스타일) / 비교 표는 `comparison` |
| `1. 2. 3.` 순서 있는 목록 (절차) | `steps` 또는 `.process` |
| 한 문장만 있는 단락 (핵심 주장) | `takeaway` / `statement` |
| `> 인용문 — 출처` | `.quote-block` / `callout-hero` |
| `> [!warning]` / `> [!tip]` 옵시디언 콜아웃 | `.callout warn` / `.callout success` |
| 큰 숫자 + 단위 나열 ("80%", "3배") | `.stat` KPI / `metric-row` |
| "Q. 질문?" + 답변 쌍 | `.stack` + `.panel` Q&A |
| 마지막 "감사합니다" / 연락처 | `end` / `thanks-contact` |

## 원고 작성 수칙 (변환 친화)

1. **한 장 분량 = 한 소제목** — H2/H3 하나 아래 내용이 불릿 6개를 넘으면 소제목을 쪼갠다.
2. **사례는 4단계로 쓴다** — 상황 → 프롬프트 → 진행과정 → 결과. 각각이 슬라이드 1장이 된다.
3. **핵심 주장은 한 문장 단락으로 분리** — 앞뒤 빈 줄로 고립시키면 takeaway/statement 후보가 된다.
4. **이미지는 문단 바로 아래에** — 해당 텍스트와 같은 장(split)으로 묶인다.
5. **숫자는 명시적으로** — "많이 빨라짐" 대신 "80~90% 단축" (stat/metric 후보).
6. **병렬 개념은 3개로 맞춘다** — 2개면 vs, 4개 이상이면 보드/분할.
